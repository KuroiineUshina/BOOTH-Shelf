# BOOTH Shelf 1.0.9 동기화 성능 개선

2026-09-08. 실제 계정에 요청하지 않고, 동일한 가상 통신·저장 지연 조건에서 변경 전후 소스를 실행해 비교했습니다.

## 변경

- 라이브러리와 지원 아바타 색인 처리의 동시 작업 수를 2 → 4로 조정했습니다. 요청 시작 간 최소 300ms 간격과 기존 재시도 대기를 유지합니다.
- 12개 묶음의 마지막 응답과 저장이 끝나야 다음 묶음을 시작하던 구조를 연속 작업으로 바꿨습니다. 진행 상태도 상품 하나가 끝날 때마다 갱신합니다.
- 중간 저장은 직렬 실행하면서 통신과 겹쳐 진행합니다. 저장이 밀리면 대기 중인 중간 결과를 최신 결과로 합치고, 마지막 저장을 기다립니다.
- 보유 상품과 연결된 아바타 상품에 같은 ID가 있으면 요청과 DOM 분석을 공유합니다. 캐시에는 작은 분석 결과만 두고 HTML 원문은 보관하지 않습니다. 캐시는 해당 동기화에만 존재합니다.
- 중간 저장으로 이미 반영된 최종 결과의 중복 저장을 제거했습니다.
- 치명적 오류가 나면 새 작업을 시작하지 않고 이미 시작한 작업과 저장을 정리한 뒤 오류를 전달합니다. 저장 실패를 성공으로 표시하지 않습니다.

## 비교 결과

표의 시간은 모의 시간입니다. 실제 BOOTH 응답 시간이나 사용자 계정에서 측정한 결과가 아닙니다. 상품 설명 비교는 실제 설명 신호 분석 코드를 사용하며 DOM 입력을 고정된 객체로 제공합니다. 라이브러리 비교는 HTML 파싱 대신 고정된 페이지 결과를 제공해 스케줄링·정렬·중복 합치기를 비교합니다.

| 조건 | 이전 | 변경 후 | 단축 |
| --- | ---: | ---: | ---: |
| 설명 48개, 응답 1.2초, 저장 80ms | 30.32초 | 15.38초 | 49.3% |
| 설명 48개, 응답 250ms, 저장 80ms | 14.52초 | 14.43초 | 0.6% |
| 설명 48개, 응답 1.2초, 저장 6초 | 54.00초 | 22.50초 | 58.3% |
| 서로 연결된 보유 상품 24개, 응답 1.2초 | 29.56초 | 10.28초 | 65.2% |
| 라이브러리 12페이지, 응답 1.2초 | 8.40초 | 5.40초 | 35.7% |

연결된 보유 상품 시나리오의 요청 수는 48 → 24회였습니다. 유효한 설명 색인 48개를 가진 경우는 이전·변경 후 모두 추가 요청과 색인 저장이 0회입니다. 모든 시나리오에서 최종 상품 데이터 해시가 일치했습니다. 응답이 이미 빠르고 중복 요청이 적으면 개선 폭은 작습니다.

## 검증

- Node 테스트 94개 통과: 기존 85개와 추가 9개.
- 추가 테스트: 4개 병렬 처리와 300ms 간격, 직렬·최종 저장, 밀린 저장 합치기, 순환 링크 중복 제거, 유효 색인 재사용, 저장 실패, 실패한 공유 요청의 다음 동기화 재시도, 429 대기, 페이지 순서·중복 위치 보존, 로그인 오류 시 진행 중 요청 정리.
- 브라우저의 기존 HTML 파서 harness 통과: 라이브러리·기프트·무료 목록, 파일 옵션, 주문 금액, 상품 설명·아바타 정체성, 로그인 감지.
- JavaScript 문법 검사와 1.0.9 버전 일치 검사 통과.

회귀 테스트: `node --test tests/sync-performance.test.js`. 전체 테스트: `npm test`.

비교 원본·실행 스크립트·결과는 `dist/sync-speed-2026-09-08/`에 있습니다. `benchmark.json`에는 비교 소스와 각 결과의 SHA-256을 기록했습니다. 실제 계정의 동기화 시간을 확인하거나 확장프로그램을 배포하지는 않았습니다.
